# FF14 繁中服連線監測工具（ff14-netmon）

FF14 繁中服常常斷線。這個 Windows 小程式會持續監測連線，在斷線當下判斷問題出在哪一段：自己的網路、ISP，還是遊戲伺服器。

```text
[你的電腦] → [Wi-Fi/網卡] → [路由器] → [ISP] → [國際路由] → [FF14 繁中服伺服器]
```

## 下載與使用

- 到 [Releases](https://github.com/DuridMing/FFXIV_netmon/releases/latest) 下載 `ff14-netmon.exe`，點兩下就能用，不需要安裝。
- 第一次開啟時如果出現 Windows SmartScreen 警告，請按「其他資訊」→「仍要執行」。這個程式沒有數位簽章，所以會出現這個警告。
- 畫面怎麼看、斷線時要看什麼，請看 **[使用手冊](USAGE.md)**。

## 功能

- **自動找出遊戲伺服器**：讀取 `ffxiv_dx11.exe` 的 TCP 連線，不用手動填 IP。
- **分層監測**：每 2 秒量測各層的延遲、抖動和掉包率。

  | 層級 | 目標 | 方法 |
  | --- | --- | --- |
  | L1 | Wi-Fi 訊號（有線網路不顯示） | WLAN API |
  | L2 | 路由器（預設閘道） | ICMP ping |
  | L3 | ISP（traceroute 第 2–3 跳） | ICMP ping |
  | L4 | 外部網路（1.1.1.1） | ICMP ping |
  | L5 | 遊戲伺服器 | TCP ping（伺服器常擋 ICMP） |

- **異常偵測**：以下任一情況算一次異常，會自動跑 traceroute 並記錄當下各層的數據。30 秒內接連發生的異常會併成一次，不會一直重複通知；這段期間才開始的問題，如果 30 秒後還沒恢復，會再回報一次。
  - 遊戲的 TCP 連線全部中斷
  - 遊戲伺服器連續 3 次逾時
  - 任一層最近 20 秒掉包 ≥ 20%
  - 延遲突然升高（≥ 150 ms，而且是近期平均的 3 倍以上）
  - 遊戲連線重傳變多，或發生重傳逾時（需要系統管理員權限）
- **自動診斷**：依最早出問題的那一層判斷。

  | 現象 | 判斷 |
  | --- | --- |
  | 路由器也掉包 | 家中網路問題（Wi-Fi 訊號偏弱時會建議改用有線） |
  | 路由器正常、ISP 掉包 | ISP 問題 |
  | 外部網路（1.1.1.1）也掉包 | 對外網路問題 |
  | 只有遊戲伺服器掉包 | 伺服器或國際路由問題，並指出從第幾跳開始掉包 |
  | ping 正常，但遊戲連線一直重傳 | 遊戲連線的路徑在掉包 |
  | 全部正常但遊戲斷線 | 伺服器主動斷線或維護 |
  | 出問題時這台電腦正在大量下載或上傳 | 本機大量傳輸（例如 Steam、Windows Update、雲端同步） |
  | 延遲是從某一跳換了位址之後才變高 | ISP 改了到遊戲伺服器的路由 |
  | 遊戲連線在電腦睡眠期間中斷 | 睡眠造成的，不是網路問題 |

- **記錄檔**：每 2 秒的量測結果和異常事件都存在 `%LOCALAPPDATA%\ff14-netmon\netmon.db`（SQLite），量測樣本保留 30 天。
- **報告匯出**：按「匯出報告」選擇範圍（最近 24 小時、7 天或 30 天），會把 HTML 報告（各層統計、每小時或每日狀況、異常事件）和 CSV 存到「文件\ff14-netmon」，並自動開啟報告。可以交給 ISP 或遊戲客服當證據。
- **系統匣常駐**：按視窗的 X 會縮到系統匣繼續監測。圖示顏色代表連線狀態（綠／黃／紅），滑鼠移上去可以看到目前延遲。右鍵選「結束」才會關閉程式。也可以在「設定」改成按 X 直接結束。
- **延遲圖表**：顯示最近 10 分鐘各層的延遲，掉包用紅點標示。滑鼠移到圖上可以看到那個時間點各層的數值。
- **清除紀錄**：在「設定」裡可以清除所有記錄，清除前會先確認。
- **遊戲連線 TCP 統計**：讀取 Windows 對遊戲那條連線的實際延遲、重傳封包數和重傳逾時次數。這最接近遊戲裡的真實狀況，重傳逾時連續發生就是 90002 斷線的前兆。需要以系統管理員身分執行，介面上有按鈕可以直接重新啟動。
- **中間節點追蹤**：持續追蹤到遊戲伺服器路徑上的每一個節點（類似 MTR），找出從哪一跳開始掉包。ISP 改了路由時會記錄下來，並比較變更前後的延遲。
- **長期統計**：匯出報告可以選最近 24 小時、7 天或 30 天。長範圍的報告有每日趨勢和「星期 × 小時」熱度表，可以看出哪個時段最常出問題。
- **不影響遊戲**：介面用省電的內顯繪製（沒有內顯的電腦會用唯一那張顯示卡），開啟時也不會搶走遊戲的焦點。如果電腦不支援 DirectX 12，會自動改用 OpenGL 或 Windows 內建的軟體繪圖。
- **網卡斷線偵測**：網路線鬆脫、Wi-Fi 斷線或網卡被停用時，會直接告訴你是電腦本身的網路斷了。換網路（例如從 Wi-Fi 換成有線、開關 VPN）時，會自動重新找路由器和 ISP 節點。用 VPN 或電腦直接撥號（PPPoE）時沒有路由器，路由器那層會顯示「無目標」，其他層照常量測。有線網路的連線速度從 1 Gbps 以上掉到 100 Mbps 以下時也會提醒，多半是網路線或接頭接觸不良。
- **睡眠恢復**：電腦從睡眠或休眠恢復後，會先等網路重新連上再開始判斷異常，睡眠期間的斷線不會被當成網路問題。
- **只會開一個**：重複開啟時，會把已經在執行的視窗叫出來。
- **異常通知**：發生異常時跳出 Windows 通知，內容包含診斷結論。可以在視窗右上角關閉。
- **Wi-Fi 訊號**：顯示目前連線的 Wi-Fi 和訊號強度。家中網路出問題、而且訊號偏弱時，會建議改用有線網路。

### 安全性

本工具只讀取 Windows 的連線資訊，不讀取、注入或修改遊戲封包，也不碰遊戲程序本身。

## 技術

- 語言：Rust
- 介面：eframe / egui，用 wgpu（DirectX 12）繪製，並優先使用省電的內顯，不跟遊戲搶獨立顯示卡。初始化失敗時依序改用 OpenGL、Windows 軟體繪圖（WARP）
- 圖表：egui_plot
- 呼叫 Windows API：`windows` crate
  - `IcmpSendEcho`：ICMP ping，不需要系統管理員權限
  - `GetExtendedTcpTable`：找出遊戲連線
- 資料儲存：SQLite（`rusqlite`）
- 大小：單一 exe，約 8 MB（上限 10 MB），不需要另外安裝任何東西

## 開發環境設定

1. 安裝 [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，勾選「使用 C++ 的桌面開發」。Rust 在 Windows 上要用到它的連結器。
2. 安裝 Rust：

   ```powershell
   winget install Rustlang.Rustup
   ```

   也可以從 <https://rustup.rs> 下載 `rustup-init.exe` 安裝。
3. 重新開啟終端機，確認有裝好：

   ```powershell
   rustc --version
   cargo --version
   ```

## 建置與執行

```powershell
cargo run                                  # 開啟監測視窗，自動偵測遊戲伺服器
cargo run -- --target 203.0.113.10:55006   # 手動指定目標（沒開遊戲時測試用）
cargo run -- --renderer gl                 # 指定繪圖方式：dx12（預設）、gl、warp
cargo build --release                      # 正式版，輸出在 target\release\
cargo test                                 # 單元測試；需要網路的測試加上 -- --ignored
```
